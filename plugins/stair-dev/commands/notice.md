description: Read Stair's privacy notice in short and choose whether it records - after the notice changed, or any time
---

The person typed this command to read Stair's privacy notice and choose. Only they decide; your part is to show the notice faithfully and do what they choose.

The plugin's directory is `${CLAUDE_PLUGIN_ROOT}`; its name is the `name` in `.claude-plugin/plugin.json` there (`stair`, or `stair-dev` for the staging channel, whose command is `stair-dev` and state directory `~/.stair-dev`).

1. Run `"${CLAUDE_PLUGIN_ROOT}/bin/stair" rl status` and note `privacy_notice` (the version they accepted, if any), `privacy_notice_installed`, `uploads_paused`, `waiting_sessions`, `this_session_waiting`, `reload_needed` and `installed_now`. If `configured` is false, Stair is not set up on this machine: tell them `/stair-dev:install` sets it up, and stop. If `reload_needed` is true, this session still runs an earlier version of Stair than the one installed (`installed_now`), and the notice it would show is that earlier version's: ask them in one line to type /reload-plugins in the prompt box, which switches this session to the installed version, and then /stair-dev:notice again (only they can type /reload-plugins; over Remote Control or on the phone, a new session does the same), and stop. If `uploads_paused` is true but the accepted version is already the installed one, the makers published a newer notice than this plugin has: offer to update the plugin (`claude plugin marketplace update stair-ai-dev && claude plugin update stair-dev@stair-ai-dev`, for `stair-dev` the marketplace `stair-ai-dev`); after the update, ask them in one line to type /reload-plugins and then /stair-dev:notice again, and stop here. Otherwise read `PRIVACY.md` in the plugin directory in full: you answer questions from it.

2. Show them, exactly as written (translate faithfully if they write in another language): when the accepted version is older than the installed one, first the line "Stair's privacy notice changed (ACCEPTED to INSTALLED). What the new version records waits on this machine until you choose. Sessions so far: N, this one included.", with the real versions and `waiting_sessions` for N, leaving out ", this one included" when `this_session_waiting` is false and the whole last sentence when N is 0; then the whole "In short" section of `PRIVACY.md`; then, when it changed, every entry of its "Changes to this notice" section newer than the accepted version, newest first; and last the line "The full notice is PRIVACY.md (version INSTALLED); ask me anything about it."

3. If the installed version is the accepted one, say they accepted it (with the date, from `accepted_at`) and that nothing needs doing; stop. Otherwise ask one question with AskUserQuestion, "Accept notice INSTALLED and go on recording?", none of the options marked as recommended: when sessions wait (N is not 0), "Yes, and send the waiting sessions (N)", "Yes, but leave the waiting sessions out" and "Not now"; when none wait, "Yes" and "Not now". When `this_session_waiting` is true, the description of each of the first two says what it does to this session, which is one of them: sent with them, or left out with them (then nothing of this session is recorded, and their next session records as usual). If AskUserQuestion is not available, or the question box cannot be shown (the call fails or comes back without an answer), ask the same question in your message with the choices numbered, and wait for their reply; act only on a clear choice. Answer their questions from `PRIVACY.md` before they choose.

4. Do what they chose. Yes: run `"${CLAUDE_PLUGIN_ROOT}/bin/stair" rl accept-notice INSTALLED`, adding `--skip-waiting` if they chose to leave the waiting sessions out, and say in one line what it did: `waiting_sessions_released` sessions start uploading when this turn ends and go on in the background (a long history can take hours), `waiting_sessions_left_out` are left out, and, when it is not zero, `waiting_sessions_unavailable` could not be sent because their record is no longer on this machine; when `this_session` is not null, add that this session is one of them (left out, nothing of it is recorded, and their next session records as usual). Not now: run `"${CLAUDE_PLUGIN_ROOT}/bin/stair" rl notice-later`, which changes nothing but the reminder (no line about this notice at the start of a session for a week), and say that what the new version records stays on this machine until they accept, that the reminder stays quiet for a week, that `/stair-dev:notice` brings them back here any time, and that `claude plugin uninstall stair-dev@stair-ai-dev` stops Stair altogether.
